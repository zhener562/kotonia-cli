# フォルダごとの記憶 (2026-11-03)

作業フォルダごとに長期記憶を持たせ、ホームの USER.md (ユーザーが誰か・好み) を全フォルダで共有する。
実装は `src/project.rs`、配線は `Agent::new` (CLI・daemon・kotonia-desktop が同じ経路を通る)。

```
~/.kotonia/projects/
  grants.json                 フォルダごとのメール許可 (人だけが編集する)
  <フォルダ名>-<8桁>/
    ROOT                      どのフォルダの記憶か
    MEMORY.md                 このフォルダについて残す事実
    memory/YYYY-MM-DD.md      日々のメモ
```

## 決めたこと

- **キーはメインの worktree のルート**。CLI は毎回 `/tmp/kotonia-agent-xxxx` の worktree で動くので、
  cwd をキーにすると毎回空の記憶になる。サブディレクトリから起動しても同じキー
- **USER.md はコーディングのセッションにも渡す** (user 判断)。数百字で、好みや話し方を覚えていたほうが
  やり取りの無駄が減る。テンプレートのままなら送らない
- **書き込みは `memory` ツールだけ**。bash は記憶ファイル・grants.json・ホームの USER.md に触れられない
  (承認モードに関係なく拒否)
- **承認を求めるのは、セッションがメールか Web の内容を読んだ後の書き込みだけ**。外から来たテキストが
  「これを覚えておけ」と書いて、以後のすべてのセッションに残る経路を止めるため
- **メールはフォルダ単位で人が許可する** (`kotonia-cli project allow-mail <id>`)。ホームモードは従来どおり全アカウント
- bash からの `kotonia-cli mail` はホームモード以外で拒否する。それまで allowlist に入っていて、
  どのコーディングセッションからも承認なしでメールを読めた

## 却下した案

- **リポジトリ内に `.kotonia/MEMORY.md` を置く**: `git add .` でユーザーについてのメモまで公開リポジトリに push される。
  チームで共有する指示はリポジトリの AGENTS.md に置く
- **cwd をキーにする**: worktree ごとに記憶が分裂する
- **書き込みのたびに承認を求める**: いつも聞かれると読まずに押すようになる (ホームで、承認経由で保管庫を読まれた前例がある)
- **メール許可をエージェントが書ける場所に置く**: 読んだテキストが権限を付与できてしまう

## 残っている穴 (未対応)

- ホームの MEMORY.md / AGENTS.md / TOOLS.md などは今も bash で書ける。外部テキストが居座る経路が残っている
- 承認の対象として数えているのはメール・Web・シェルからのダウンロードだけ。リポジトリ内のファイル (悪意のある README など) は数えていない
- 再開したセッションでは、過去に読んだ Web の内容を検出できない (メールは囲いの印で検出する)
- bash の判定は文字列で見ているだけ (保管庫と同じ水準)。パスを組み立てるスクリプトならすり抜けられる
- heartbeat には `memory` ツールが無く USER.md を書けないが、ホームのプロンプトは `memory` ツールで書けと言っている
- 旧方式 (delimiter) のループでは記憶は読み取り専用
- desktop にメール許可の画面は無い (CLI のみ)
- 許可したフォルダで実際にメールを読む動作は、本物の受信箱では未確認
